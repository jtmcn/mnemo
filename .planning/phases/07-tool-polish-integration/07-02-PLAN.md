Add a new test class `TestLifecycle` at the end of `tests/test_mcp.py`. This tests the full add -> search -> update -> verify -> remove -> verify removal cycle.

Use the hybrid approach from RESEARCH.md: mock `ingest.ingest_book` (to avoid real EPUB parsing + embedding) but use real temp DB for everything else. For the search step, use keyword-mode search against a real temp FTS5 database (no embeddings needed).

Implementation:

```python
class TestLifecycle:
    """End-to-end lifecycle: add -> search -> update -> verify update in info -> remove -> verify removal."""

    @pytest.fixture
    def temp_db(self, tmp_path):
        """Create a temporary database."""
        from mnemo.storage.database import get_connection, init_db
        db_path = tmp_path / "test.db"
        init_db(db_path)
        conn = get_connection(db_path)
        yield {"path": db_path, "conn": conn}
        conn.close()

    def test_full_lifecycle(self, tmp_path, temp_db):
        """Full lifecycle: add, search, update, verify, remove, verify gone."""
        from mnemo.mcp import tools
        from mnemo.storage import BookRepository, ChunkRepository

        # Prepare a fake EPUB file
        epub_file = tmp_path / "lifecycle.epub"
        epub_file.write_bytes(b"fake epub content")

        # Mock book that ingest_book "creates"
        lifecycle_book = Book(
            id="lif001",
            title="Lifecycle Test Book",
            authors=["Test Author"],
            isbn="978-0000000000",
            file_hash="lifecycle" + "a" * 56,
            default_language="python",
            structure_source="toc",
            added_at=datetime(2026, 2, 16, tzinfo=timezone.utc),
        )

        # Mock pre-parsed metadata (extract_metadata result)
        mock_pre_parsed = MagicMock()
        mock_pre_parsed.file_hash = lifecycle_book.file_hash
        mock_pre_parsed.title = lifecycle_book.title

        # --- Setup: wire tools to temp DB ---
        original_conn = tools._db_connection
        original_service = tools._search_service
        tools._db_connection = temp_db["conn"]
        tools._search_service = None  # Reset so it doesn't use production

        try:
            # --- Step 1: Add book ---
            # Mock ingest_book to insert the book into our temp DB and return it
            def mock_ingest(path, embed=True, force=False):
                book_repo = BookRepository(temp_db["conn"])
                book_repo.add(lifecycle_book)
                # Also add chunks so search and get_book_info work
                chunk_repo = ChunkRepository(temp_db["conn"])
                chunks = [
                    Chunk(
                        id=f"lc-chunk-{i}",
                        book_id="lif001",
                        content=f"Lifecycle content about Python decorators part {i}",
                        content_type=ContentType.TEXT,
                        token_count=10,
                        section_path=["Chapter 1", f"Section {i}"],
                        sections=["Chapter 1"],
                        language=None,
                        sequence=i,
                    )
                    for i in range(3)
                ]
                chunk_repo.add_many(chunks)
                return lifecycle_book, 3

            with (
                patch("mnemo.epub.metadata.extract_metadata", return_value=mock_pre_parsed),
                patch("mnemo.ingest.ingest_book", side_effect=mock_ingest),
            ):
                add_result = tools._add_book_impl(str(epub_file))

            assert "Added" in add_result
            assert "Lifecycle Test Book" in add_result
            assert "3 chunks" in add_result

            # --- Step 2: Search for content ---
            # Use keyword search against the real FTS5 table (no embeddings needed)
            # We need a SearchService pointing at the temp DB
            from mnemo.search import SearchService
            temp_search = SearchService(db_path=temp_db["path"])
            tools._search_service = temp_search

            search_result = tools._search_books_impl("Python decorators", mode="keyword")
            assert "decorators" in search_result.lower()
            assert "lif001" in search_result

            # --- Step 3: Update metadata ---
            update_result = tools._update_book_metadata_impl("lif001", title="Updated Lifecycle Book")
            assert "Updated Lifecycle Book" in update_result

            # --- Step 4: Verify metadata reflected in get_book_info ---
            info_result = tools._get_book_info_impl("lif001")
            assert "Updated Lifecycle Book" in info_result
            assert "Test Author" in info_result

            # --- Step 5: Remove book ---
            with patch("mnemo.ingest.remove_book") as mock_remove:
                mock_remove.return_value = True
                remove_result = tools._remove_book_impl("lif001")

            assert "Removed" in remove_result
            assert "Updated Lifecycle Book" in remove_result

            # --- Step 6: Verify removal ---
            gone_result = tools._get_book_info_impl("lif001")
            assert "not found" in gone_result.lower()

        finally:
            tools._db_connection = original_conn
            tools._search_service = original_service
```

Key design decisions:
- `mock_ingest` inserts real data into the temp DB so search and get_book_info work against real rows
- Search uses keyword mode against FTS5 (no embedding API needed)
- SearchService is instantiated with `db_path=temp_db["path"]` -- check if SearchService accepts a `db_path` parameter. If not, mock the search service with a real FTS query or use `tools._search_service` override with a properly configured service. Adapt the approach to match the actual SearchService constructor.
- `remove_book` is mocked (pipeline manages its own DB connections, tested elsewhere)
- Each step's output is asserted before moving to the next

IMPORTANT: Before writing the test, read `src/mnemo/search/__init__.py` and `src/mnemo/search/service.py` (or wherever SearchService is defined) to understand how to instantiate it with a temp DB path. Adapt the test accordingly. If SearchService cannot be easily pointed at a temp DB, mock the search step to return canned results from the temp DB data.
